# Chatbot-as-a-Service — Embeddable Widget

## Purpose
A dependency-free vanilla-JS chat widget that any website embeds with one `<script>` tag to get the client's AI sales assistant, product carousel, cart, Razorpay / COD checkout — identified only by API key.

## Scope
- **In:** `frontend/public/chatbot-widget.js`, its Shadow-DOM UI, config, streaming client, cart mirror, variant gating, tests.
- **Out:** server behaviour (`chatbot-service-agent`), client setup and embed snippet (`chatbot-service`).

## Functional behaviour
- **Embed:** `window.RCChatbotConfig = { apiKey, apiBase?, position? (right | left), primaryColor?, accentColor? }` + `<script src="https://app.silarai.com/chatbot-widget.js" async>`. Without `apiBase` it falls back to the production Azure API URL (it has no build-time env). *Order now* pins the product in a focus strip (focused mode, `chatbot-service-agent`) until it is cleared.
- **UI:** launcher + teaser → panel with a single-row header (avatar, name, cart button with count, close); optional focused-product strip; grouped messages; product carousel (drag-to-scroll); product **detail** as a full in-panel overlay (hero image, variant grid, *Add to cart*, *Order now*, sticky Back bar); cart as a **bottom sheet** over the messages; auto-growing composer (Enter sends, Shift+Enter newline); Escape closes overlays / panel.
- **Streaming:** requests NDJSON and renders the server's *thinking* line, then the final reply; falls back to the single-JSON response.
- **Cart:** a read-only mirror of the server cart — every change round-trips `POST /chatbot/{apiKey}/cart` and re-renders what comes back. `sessionId` lives in `localStorage["rc_s_" + apiKey]` and is re-synced from the server.
- **Variants:** a product with variants can't be added or ordered in one tap — the card's *Add* opens the detail sheet; both detail buttons stay disabled (with a `.vrow.shake` cue) until a variant is chosen.
- **Order now** writes the cart directly (same `addToCart` call as *Add*) and only then sends a generic *"I'd like to checkout"* to the chat — the model never performs that write.
- **Checkout:** COD or Razorpay (key id from `config`), then `verify-payment`.

## Rules
- **CBS-R8** — The widget must stay backward compatible (legacy JSON and NDJSON responses; tolerate the `cart` key present or absent); deploys require cache-busting the embed URL.
- **CBS-R15** — Everything renders inside one open Shadow DOM on a full-viewport `position:fixed`, `pointer-events:none` host (only launcher, teaser and panel re-enable pointer events). Never give the host a `transform`; use `root.getElementById` / `root.querySelector`, not `document.*`.
- **CBS-R16** — No external requests besides the API (no web fonts); brand colours are host CSS variables (`--rc-primary` + precomputed `--rc-primary-a08/15/40/55`, computed in JS — no `color-mix()`).
- **CBS-R17** — Layout traps not to reintroduce: every child of the column-flex `.msgs` needs `flex:0 0 auto` (scroll containers otherwise collapse); carousel drag must not call `setPointerCapture` on `pointerdown` (it retargets the click and kills card buttons) — capture only after the drag threshold.
- CBS-R6 / CBS-R7 apply (variants, direct button writes).

## Backend
Uses `GET {apiKey}/config`, `POST {apiKey}/message`, `GET {apiKey}/products`, `GET|POST {apiKey}/cart`, `POST {apiKey}/orders/{id}/verify-payment` (`chatbot-service-agent`).

## Frontend
- **Code:** `frontend/public/chatbot-widget.js` (outside the Vite build, never type-checked).
- **Tests:** `frontend/test/chatbot-widget.test.mjs` — jsdom against a mocked API: shadow-root isolation, NDJSON streaming, thinking line, card values, cart flow, Escape, non-streaming fallback. Run `npm install --no-save jsdom && node test/chatbot-widget.test.mjs`. This is the widget's only automated coverage.

- 2026-08-18 — **Chatbot embed snippet pointed at a host that doesn't serve the widget** — `VITE_APP_URL` in `.github/workflows/azure-static-web-apps-lemon-sea-09c8e5a00.yml` was `https://www.silarai.com` (the WordPress marketing site), so the copy-paste embed generated by `AdminChatbotClientDetailPage.tsx` loaded `https://www.silarai.com/chatbot-widget.js` → 404 and no launcher rendered; changed to `https://app.silarai.com` (the Azure SWA origin that actually serves `frontend/public/`).
- 2026-08-12 — **Chatbot variants: a product with options can no longer be added, ordered, or falsely narrated as added** — `frontend/public/chatbot-widget.js` gates the card Add button (now "Select", opens the detail sheet), `#pdAdd` and `#pdOrder` on a chosen variant and makes Order now write the cart directly via `addToCart` before handing off to chat rather than relying on the model to call `update_cart`; server-side `ChatbotAgentTools.ExecuteCartUpdate` holds back variant-less `add`/`set` ops and `ChatbotAgentPromptBuilder` forbids narrating a cart change that didn't happen. Widget suite 69 assertions pass; C# reviewed by hand, not compiled (no dotnet SDK available in that environment).
- 2026-08-01 — **Fix: vertical scrolling froze while the cursor was over the product carousel** (`frontend/public/chatbot-widget.js`). The rail carried a `wheel` handler (inherited from the pre-redesign widget) that mapped vertical wheel onto horizontal scroll and only released it at the rail's extremes — so hovering a card stopped the conversation from scrolling. More noticeable after the redesign because the taller cards make the rail a much larger hit target. Handler removed entirely: vertical wheel now falls through to the message list, while Shift+wheel, trackpad swipes and touch already scroll the rail natively. To keep horizontal scrolling discoverable for plain-mouse users (drag-to-scroll alone is not obvious), added prev/next arrow buttons in a new `.railwrap` container — hidden when the cards fit, and each arrow hides at its own end. Added 7 assertions (51 total), verified to fail if the wheel hijack is reintroduced.
- 2026-08-01 — **Fix: card "Add" and card-tap were dead; product detail restored to a full in-panel view** (`frontend/public/chatbot-widget.js`).
  - Root cause of both: the carousel's drag-to-scroll called `rail.setPointerCapture()` on `pointerdown`. While a pointer is captured the browser retargets the following `click` to the capturing element, so every click inside a card landed on the rail and neither the Add button nor the card body ever fired. Capture is now taken only after the pointer moves past the 5px drag threshold — which a plain click never crosses — so clicks are untouched and drag-to-scroll still works. Also ignores non-primary buttons and stray pointer ids.
  - Product detail moved from a bottom sheet back to a full in-panel overlay (`.detail`, `position:absolute; inset:0` inside the panel) with a sticky Back bar and a sticky action row, matching the pre-redesign behaviour. The cart deliberately stays a bottom sheet — it is a short list and benefits from keeping the conversation visible. `openDetail`/`closeDetail` are now separate from `openSheet`/`closeSheets`; Escape and order placement close both.
  - Added test coverage that was missing: Add-from-card actually posts to `/cart`, a simulated drag does NOT open the detail view, a plain tap does, and Back closes it. 44 assertions total.
- 2026-08-01 — **Widget now tolerates PascalCase responses (backend/widget version skew).** After the streamed-serialisation fix landed in source, a running-but-not-yet-rebuilt API still returned `Title`/`Price`/`ImageUrl`, which rendered the carousel as blank ₹0 cards — the data was all present, only the casing differed. `chatbot-widget.js` now runs every network payload through `camelKeys()` (recursive first-letter lower-casing) at three boundaries: `applyTurn`, `setCart` and `loadConfig`. This matters structurally, not just for this incident: the widget is loaded directly by third-party sites with no version coupling to the API, so new-widget/old-server and old-widget/new-server skew are both permanent conditions. Warns once via `console.warn` when PascalCase is seen, so a stale deploy still surfaces rather than being silently masked. Added 5 test assertions covering a PascalCase turn (39 total); verified they fail without `camelKeys` and pass with it.
- 2026-08-01 — **Fix: product carousel collapsed to a bare scrollbar, and the composer rendered a native scrollbar** (`frontend/public/chatbot-widget.js`). Both regressions from the Shadow DOM rewrite earlier today.
  - Carousel: `.msgs` is a column flex container and `.rail` is a horizontal scroll container. A scroll container's automatic minimum size is `0` (not `min-content`), so the rail was shrunk to nothing and only its scrollbar remained visible. The pre-rewrite `.rc-scroller` had `flex-shrink:0`; that pin was lost in the rewrite. Restored via `.msgs > *{flex:0 0 auto}` plus an explicit `flex:0 0 auto` on `.rail`. Also gave `.card .ph` an explicit `height:150px` alongside `aspect-ratio`, since aspect-ratio alone leaves older WebViews at zero height.
  - Composer: `autoGrow()` ran at bootstrap while the panel was still `display:none`, so `scrollHeight` was 0 and the textarea was pinned to `height:0px` — which is why a native vertical scrollbar (the stacked arrows) appeared over the field. `autoGrow()` now bails when `scrollHeight` is 0, clamps to a 34px floor, and toggles `overflow-y` to `auto` only past the 96px cap; the bootstrap call was dropped and `doOpen()` calls it at first measurable layout instead. Textarea defaults to `overflow-y:hidden`.
  - Hid `::-webkit-scrollbar-button` on `.msgs` and `.rail` (native arrow buttons were showing through on Windows).
  - Added 5 CSS-level regression assertions to `frontend/test/chatbot-widget.test.mjs` (34 total). Verified they fail against the broken build and pass against the fix — jsdom has no layout engine, so these assert the CSS rules rather than geometry.
- 2026-08-01 — **Chatbot widget rewritten: Shadow DOM isolation + refreshed visual design + reworked layout** (`frontend/public/chatbot-widget.js`). Embed contract unchanged (one script tag, same `window.RCChatbotConfig`, same endpoints).
  - All markup and CSS now render inside an open shadow root on a single host `<div>`, so embedder CSS cannot reach the widget and vice versa. Host is a full-viewport `position:fixed` overlay with `pointer-events:none`; only the launcher, teaser and panel re-enable pointer events. Element lookups moved from `document.getElementById` to `root.getElementById`.
  - Theming moved to CSS custom properties set on the host (`--rc-primary` + precomputed `--rc-primary-a08/a15/a40/a55`) instead of interpolating colours into a CSS template string. Alpha variants are computed in JS rather than `color-mix()` for older Android WebView support. Dropped the Google Fonts `@import` in favour of the system font stack — one less render-blocking third-party request on the embedder's page.
  - Layout rework: cart moved from a collapsible bar wedged above the composer into a header button + bottom sheet; product detail moved from a full-panel overlay (which hid the header) to a second bottom sheet; header collapsed to a single row; composer is now an auto-growing textarea (Enter sends, Shift+Enter newline); consecutive same-sender messages group under one avatar; product cards reduced from two competing buttons to one `Add` with the card body opening detail; added discount badges, square image wells and empty-cart state; added Escape handling (closes sheet, then panel), `:focus-visible` rings and a `prefers-reduced-motion` block; panel goes full-screen and hides the launcher under 480px.
  - Fixed a listener leak: the carousel's drag-to-scroll previously attached `pointermove`/`pointerup` handlers to `window` on every render and never removed them; now uses pointer capture scoped to the rail.
  - Added `frontend/test/chatbot-widget.test.mjs` — 29 jsdom assertions covering shadow-root isolation, NDJSON streaming and the thinking line, card field values, product detail, cart add/total, and Escape; re-run with streaming disabled to cover the legacy single-JSON fallback. Run: `npm install --no-save jsdom && node test/chatbot-widget.test.mjs`.
